# Content Operations Guide v1

В рамках перехода на новую микросервисную архитектуру (Агент 2), мы используем `Excel (XLSX)` как главный Source of Truth для контента и коммерческих параметров 10 сервисных страниц.

## Основной процесс (Pipeline)

1. Контент-менеджер (или Агент 1) заполняет/обновляет файл `scripts/content/services-master.xlsx`.
2. Разработчик (или система CI/CD) запускает валидационный скрипт конвейера:
   ```bash
   npm run content:sync
   ```
3. Скрипт (`import-services-xlsx.ts`) делает полное сканирование файла, валидирует схему через TypeScript Zod и выгружает чистый `src/generated/services-content.json`.
4. Изменения сохраняются в Git вместе с кодом.

## Структура листов XLSX-файла и типы данных

Здесь описано назначение основных листов в Workbook. Внимание: имена листов и колонок менять нельзя!

### 1. services (Базовые параметры направления)

Отвечает за карточку, url (`slug`) и цвет.

- `id` — внутренний GUID (например, `aps-base`).
- `slug` — часть урла (например, `aps` → `/services/aps`).
- `title` — полное маркетинговое название.
- `shortName` — короткое (аббревиатура) для бейджей.
- `themeColor` — hex-код акцентного цвета (например, `#EF4444`).
- `isActive` — `true` / `false` (скрывает страницу из генерации).

### 2. hero (Первый экран)

- `service_slug` — должен совпадать со `slug` из `services`.
- `title` / `subtitle` — тексты.
- `trustFactors` — через запятую: `"Лицензия МЧС, Монтаж по ГОСТ, 15+ объектов"`.
- `disclaimer` — например, `"Смета после детального ТЗ"`.

### 3. stats_cards (Метрики)

- `label` — название (например, `"Скорость аудита"`).
- `value` — (например, `"24 часа"`).
- `subValue` — уточнение (`"С момента заявки"`).
- `isMarketing` — `true/false`, пометка для disclaimer.

### 4. catalog_items (Основной прайс-лист)

Обязательный лист для формирования Project Tray.

- `priceType` — должно быть строго: `from`, `range`, `fixed`, `request`.
- `priceMin` / `priceMax` — числовое значение стоимости. `priceMax` обязателен для типа `range`.
- `currency` — `RUB` по умолчанию.
- `includes` / `excludes` / `objectTypes` — списки через запятую.

### 5. solution_kits (Пакетированные решения)

Для карточек готовых кейсов (Типовой набор оборудования для 100 кв.м).

- `targetObject` / `useCase`.
- `includedItemCodes` — через запятую список `itemCode` из каталога. Автоматически добавляет 1 единицу каждого при клике на "Добавить в проект".

## Валидация

Скрипт проверяет бизнес-правила:

1. `priceMin` не может быть меньше `0`.
2. Если указаны min и max, то `priceMin <= priceMax`.
3. Услуги без связи по `service_slug` в `catalog_items` игнорируются.

Вопросы и предложения можно передать через GitHub Issues (Агент 2).
